# Changelog

## 0.1.0

- First packaged release with Telegram onboarding, meal planning, shopping, training and an optional web page.
- Added provider consent, offline manual degradation, operator health checks and a disposable example demo.

## Unreleased

- Container: `web.bind_trusted_network` (off by default) allows binding beyond loopback behind a proxy; `CLAUDE_CODE_OAUTH_TOKEN` now reaches the Claude CLI child.
- Sign-in: Telegram is the default; `header` mode needs `web.trusted_header_proxy`; the sign-in link opens a confirm button instead of being used by a preview; cookies are `SameSite=Lax`; devices are signed out after 14 idle days (schema 6, `web_device_seen`); `web.signed_out_redirect`; the manifest is fetched with credentials.
- Container: hardened Dockerfile and compose example, `python -m tiffin.healthcheck`, doctor recognises a container, `TIFFIN_<NAME>_FILE` secrets, `TIFFIN_CLAUDE_OAUTH_TOKEN` for the Claude CLI on a server.
- Linking: two people connect with a code (`/link`, or More on the page) before they can share weekends; sharing needs a link and both people's yes (`linked_and_both_consented`). Either can unlink at once; built weekends stay as two ordinary menus and the open joint shopping list closes into one copy each. Schema 7: `links`, `link_events`, `link_attempts`, `shopping_list_closures`, `link_id` on `shared_menus` and `shopping_lists`. `links.record_migrated` records an existing pair.
- Consent text now names the machine (`[hosting]`), Telegram, the model destination and anything fronting the page; new grants are recorded as `v4`, earlier ones are honoured unchanged.
- Review fixes: a weekend stored while no link is active is stored as two ordinary menus (a `NULL` link means only "from before links"); the page's write token is signed to the session with a server key (`web-csrf-key`), not a cookie; public `/api/health` returns the status word only; `env = "dev"` is refused with a public https `web.origin`; `tiffin doctor` warns when a public https address is paired with default `[hosting]` words; erasing a linked person gives the other their copy of the open joint list; the compose example uses `restart: on-failure:5`.
- Missed messages: `tiffin status` lists `missed_slots` (job, slot, person id, due time, reason, `late` or `missed`) for each expected morning and evening message that has not gone 15 minutes after its time, and `tiffin doctor` gains an "expected messages" check. It reads the run ledger and sent messages only (no schema change). A skipped run with its reason, a paused person, a quiet-window drop, a person with no chat, a day before their first profile and anything before the first recorded run are not listed.
- Stopping: `tiffin run` handles SIGTERM, SIGINT and Ctrl+Break, ends its Telegram poll on the way out and gives work in flight 20 seconds; a 409 is retried for two minutes (the scheduler waits meanwhile) before it is called a second poller and ends the process with exit code 3; `home` and `tmp` are created under the data directory at start; the compose example adds `init: true` and `stop_grace_period: 30s`.
- `GET /api/version` (and `/version`): release and commit for the container's own check and the owner; the image takes them from `RELEASE_ID` and `RELEASE_COMMIT`, the commit also from `git archive`.
- The page: the minutes box on Today and number inputs are styled like the other fields; `docs/web-access.md` no longer says the host must be loopback.
- `tiffin setup`: a guided set-up in eight steps (home and time zone, people, Telegram, AI model, training data, web page, shopping, then a review before anything is saved). It checks the bot token with Telegram and the intervals.icu key with intervals.icu as it goes, checks the model with one tiny request only when asked after saying what that may cost, pairs each chat by a one-time code, and lets a person try again, skip an optional step or go back. Secrets are read without being shown and printed only masked. Run again, it shows what is set and changes one part (`tiffin setup web`), editing only those lines of `tiffin.toml` (comments kept, the previous file copied to `state/setup/`) and never replacing a saved secret unasked. `--non-interactive` takes flags and environment variables (`_FILE` forms included), stops with exit code 2 before writing anything when an answer is missing or wrong, changes only the parts its flags name on an existing install, and pairs by waiting, `--pair later` or `--owner-chat-id`. It ends with `tiffin doctor`'s checks and what to do next, loads an empty food list, and offers the background service. `tiffin init` and `tiffin connect <part>` run it; the intervals.icu athlete ID is no longer asked (the key names its athlete); a first run no longer leaves the packaged Claude CLI model or the placeholder web address switched on without being chosen.
- Command-line output: on a terminal `tiffin doctor` groups its checks with marks, aligned and wrapped columns and a closing verdict, and `tiffin status` is a summary in words; colour only on a terminal, never with `NO_COLOR`. Without a terminal both print exactly what they did before (status JSON; doctor's `pass|warn|fail` lines and `doctor: ok|FAIL`), with the same exit codes; `tiffin status --json` and `tiffin doctor --json` print JSON on a terminal too. Doctor's hints name `tiffin setup`.
